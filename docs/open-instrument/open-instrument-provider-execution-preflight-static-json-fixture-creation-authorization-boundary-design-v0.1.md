## Boundary decision

The implementation authorization boundary design and review are accepted.

Implementation remains blocked until a narrow implementation class is explicitly authorized.

This document designs a future static JSON fixture creation authorization boundary.

This document does not grant that authorization.

Static JSON fixture creation remains blocked until this design is reviewed and a later boundary explicitly authorizes a fixture file path.

## Static JSON fixture creation class

The future static JSON fixture creation authorization boundary may authorize only one implementation class:

- static JSON fixture creation

It must not authorize:

- JSON schema creation
- TypeScript schema creation
- validation helper creation
- validation test creation
- package script wiring
- CI workflow wiring
- provider execution
- model calls
- OpenAI API use
- runtime/API/UI wiring
- artifact/report creation
- publication framing

Any additional implementation class requires a separate boundary and review.

## Fixture file scope

A future static JSON fixture creation authorization boundary must name the exact allowed fixture file path.

The expected future file path should be:

- `docs/open-instrument/fixtures/provider-execution-preflight/open-instrument-provider-execution-preflight-static-fixture-v0.1.json`

No other fixture path is authorized by this design.

The future boundary must also state that these paths remain blocked unless separately authorized:

- `app/`
- `pages/`
- `src/`
- `components/`
- `lib/`
- `scripts/`
- `tests/`
- `.github/workflows/`
- `package.json`
- `package-lock.json`
- any provider adapter path
- any runtime/API/UI path

## Fixture content boundary

The future static JSON fixture must be static and non-executing.

It must not contain:

- live provider name
- live model name
- live endpoint URL
- API key
- secret
- credential
- token
- user data
- prompt payload for live execution
- provider response
- model output
- runtime route reference
- server action reference
- scheduled task reference
- fallback provider
- fallback model
- OpenAI fallback path
- artifact/report path
- publication framing

The fixture must use placeholder or blocked values for provider, model, and endpoint identity.

The fixture must explicitly set execution authorization flags false.

## Required non-execution declaration

The future fixture must explicitly declare:

- this fixture does not execute
- this fixture is not runnable input
- this fixture is not a provider request
- this fixture is not a model request
- this fixture is not an OpenAI API request
- this fixture is not runtime/API/UI wiring
- this fixture is not artifact/report output
- this fixture is not publication evidence

The declaration must be present in the fixture itself.

Missing declaration fails closed.

## Required decision value

The future fixture final decision must be one of:

- blocked_static_fixture_only
- static_fixture_ready_for_schema_authorization_review

No other decision value is authorized by this design.

The future fixture must not use:

- ready_for_explicit_execution_authorization
- ready_for_execution
- execution_authorized
- provider_ready
- model_ready
- publishable

Unknown decision values fail closed.

Execution-implying decision values fail closed.

A future static JSON fixture creation PR must run:

- `npm run open-instrument:validate-run-packet-fixture`
- `npx jest -c jest.config.mjs tests/openInstrument.runPacketFixtureValidation.v0.1.spec.ts --runInBand`
- `npx jest -c jest.config.mjs tests/openInstrument.runPacketFixtureValidationIntegrationGate.v0.1.spec.ts --runInBand`
- `npm run build`
- `npm run gate:quick`
- `git diff --check`

The future PR must also include an exact changed-file guard proving that only the authorized fixture file is changed.

The future PR must include a guard proving that no runtime/API/UI path changed.

The future PR must include a guard proving that no schema, script, package, CI, or test file changed unless separately authorized.
