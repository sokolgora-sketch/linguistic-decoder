# ZË-RO structural hypothesis defensibility gate review v0.1

Date: 2026-08-26

Status: Z_ZERO_STRUCTURAL_HYPOTHESIS_DEFENSIBILITY_GATE_REVIEWED_ACCEPTED_READY_FOR_RED_TESTS.

## Decision

Accepted.

The current generic reduction engine successfully proves deterministic structural surgery, but regression testing demonstrates that operation validity alone is too permissive as an emission criterion.

Observed weak outputs include:

- XYZ → YZ
- DATA → ATA
- DIJ → IJ
- MODE → ODE

These must not automatically become structural hypotheses.

## Accepted distinction

**operation eligibility != hypothesis defensibility**

The structural hypothesis layer therefore requires a separate survival gate.

## Accepted v0.1 survival rules

A terminal branch survives when:

1. it has at least two authorized structural reduction steps; or
2. it has one authorized step and the terminal consists entirely of canonical Seven Voices.

This is intentionally bounded.

It is not presented as a universal linguistic law.

It is the smallest deterministic support threshold justified for the current v0.1 proving lane.

## Accepted status rule

Logic-derived structural candidates must not contaminate stronger aggregate status ownership.

Reviewed evidence, candidate-only canonical evidence, and existing RootMap structural output keep their existing status-driving structural tokens.

Logic-derived structural tokens drive aggregate status only when they are the layer preventing an otherwise valid Null.

## Required controls

The implementation must preserve:

- STERILE → ER
- STER → ER
- SYË → YË
- xyz remains Null
- reviewed damage status/tokens unchanged
- reviewed study status/tokens unchanged
- candidate-only data status/tokens unchanged
- candidate-only dij status/tokens unchanged
- structural mode status/tokens unchanged
