## 1. Purpose

Arm A preserves the exact scratch token families in one comparable table.

This is not new evidence.

This table exists to make the already-recorded scratch tokens inspectable before any future scoring decision.

The table labels each token for:

- scratch family;
- bucket role;
- gloss;
- function class;
- part of speech;
- final shape;
- visible Finnish `i` contamination;
- token length;
- rough syllable count;
- expected visible vowel carriers;
- expected aperture region;
- inclusion reason;
- risk note.

## 3. Table notes

The labels are broad orthographic/manual curation labels.

They are not etymology claims.

They are not phonetic-acoustic measurements.

They are not automatic scorer outputs.

The `expectedApertureRegion` column is qualitative and exists only to support pre-scoring review.

Visible `i` contamination means visible Finnish orthographic `i`, not IPA-level vowel identity.

## 5. Immediate observations before scoring

Arm A shows several visible confounds that should be reviewed before any future runnable audit pack:

1. The original A/O-heavy low anchor is mostly open-final and mostly `i`-free.
2. The U-heavy V5 anchor is also `i`-free but is much more U-dense and shorter.
3. The V4-style anchor includes several final-`i` tokens:
   - `koti`
   - `ovi`
   - `onni`
4. The shared high anchor is heavily `i`-contaminated by design.
5. The open-final target is all visible-`i`.
6. The closed-final target includes one no-visible-`i` token:
   - `joutsen`
7. The target buckets mix function classes:
   - living objects;
   - body/organ;
   - place;
   - object/tool;
   - property;
   - emotion/state;
   - movement/abstract.
8. Token length differs across families:
   - U-heavy V5 anchor contains multiple very short long-vowel tokens;
   - closed-final targets are longer on average than open-final targets.

These observations support the design decision from PR #1188:

> Do not score a new Finnish `/i` audit pack until at least one curation table is repo-tracked and reviewed.

## 6. Next review questions

Before any scoring, review:

1. Should Arm B choose a single target function class, such as place/object, living object, or tool/object?
2. Should the V4-style anchor remove final-`i` tokens to reduce target-vowel contamination?
3. Should the high anchor be split into low-contamination and high-contamination versions?
4. Should the U-heavy V5 family be length-matched upward before comparison?
5. Should `joutsen` be removed or retained as an intentional no-visible-`i` target control?
6. Should Finnish front vowels `ä` and `ö` be explicitly labelled as separate front-vowel confounds?
