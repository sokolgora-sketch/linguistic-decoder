# Battery stats normalization contract v0.1

## Purpose

This document defines how numeric eval statistics from ZË-RO evidence packs should be normalized into the battery registry later.

It exists to prevent premature or invented numeric claims in the battery registry.

## Current state

The battery registry currently supports optional stats fields:

- `mainPairStats`
- `controlPairStats`

Those fields currently contain notes-only placeholders for selected cases. They must remain placeholders until real evidence-pack values are imported from actual exported artifacts.

## Source of truth

The source of truth for battery statistics is the exported eval evidence pack, not the manuscript prose and not manual chat notes.

Expected source artifacts:

- `evals.series-evidence-pack.<seriesLabel>.v0.1.zip`
- `series-summary.csv`
- per-run `report.json`
- per-run `summary.csv`
- per-run report markdown/PDF
- run metadata

## Existing eval stat fields

The eval scorer/report layer already exposes these statistical fields for intermediate-vowel runs.

### Margin permutation

- `marginPermutation.observed_min_gap`
- `marginPermutation.p_value`
- `marginPermutation.iters`
- `marginPermutation.seed`

### Effect sizes

- `effectSizes.hedges_g_low_x`
- `effectSizes.hedges_g_x_high`

### Bootstrap confidence intervals

- `bootstrap.ci95_gap_low`
- `bootstrap.ci95_gap_high`
- `bootstrap.ci95_normalizedPosition`
- `bootstrap.iters`
- `bootstrap.seed`

## Registry mapping rule

Do not collapse all evidence-pack stats into a single vague `effectSize`, `pValue`, or `ci95` field unless the field name preserves which contrast it belongs to.

A battery case has two statistical layers:

1. intended bracket statistics
2. control bracket statistics

Each bracket should preserve the internal low/x/high structure from the source run.

## Proposed normalized shape

Future registry stats should use this shape:

    export type BatteryBracketStatsV0_1 = {
      source: "evidence-pack";
      seriesLabel: string;
      evidenceZipFilename: string;

      marginPermutation: {
        observedMinGap: number | null;
        pValue: number | null;
        iters: number | null;
        seed: number | null;
      };

      effectSizes: {
        hedgesGLowX: number | null;
        hedgesGXHigh: number | null;
      };

      bootstrap: {
        ci95GapLow: [number, number] | null;
        ci95GapHigh: [number, number] | null;
        ci95NormalizedPosition: [number, number] | null;
        iters: number | null;
        seed: number | null;
      };

      notes?: string;
    };

Then `BatteryCase` should eventually expose:

    mainPairStats?: BatteryBracketStatsV0_1;
    controlPairStats?: BatteryBracketStatsV0_1;

The names `mainPairStats` and `controlPairStats` may stay for compatibility, but their inner shape must preserve the statistical source structure.

## Import rule

Only import a value when all of the following are true:

1. The evidence ZIP exists.
2. The series label in the registry matches the evidence pack series label.
3. The run ordinal set is confirmed as `[1, 2, 3, 4]`.
4. The extracted field is present in the source artifact.
5. The value can be traced to a specific file inside the evidence pack.

If any condition fails, keep a notes-only placeholder.

## No-invention rule

Never manually type numeric values into the registry from memory or manuscript prose.

Allowed:

- values parsed from evidence pack files
- values generated by deterministic repo code from committed fixtures
- notes explaining that stats are pending import

Not allowed:

- values copied from chat memory
- rounded values without source artifact
- inferred p-values
- inferred confidence intervals
- invented effect sizes

## Display rule

Battery UI may display stats only when present.

If a field is missing or null, render `—`.

Do not render missing stats as zero.

## Recommended implementation sequence

1. Keep current registry placeholders.
2. Add this contract document.
3. Locate or re-export the real evidence packs.
4. Build a parser/helper that can read:
   - `series-summary.csv`
   - per-run `report.json`
   - per-run `summary.csv`
   - per-run report markdown
5. Add tests using a small fixture evidence-pack summary.
6. Only then replace placeholder notes with structured values.

## Four-run series registry shape

The source evidence pack structure is now confirmed for four-run battery packs.

A battery case may need to preserve four separate run-level stats:

1. intended main
2. intended alt
3. control main
4. control alt

Do not collapse those four rows into one p-value.

The registry type may expose:

```ts
export type BatterySeriesRunPairStatsV0_1 = {
  bracketId: BracketId;
  main: BatteryBracketStatsV0_1;
  alt: BatteryBracketStatsV0_1;
};

export type BatteryFourRunSeriesStatsV0_1 = {
  source: "evidence-pack";
  seriesLabel: string;
  evidenceZipFilename: string;
  inspectedManifestPath?: string;
  intended: BatterySeriesRunPairStatsV0_1;
  control: BatterySeriesRunPairStatsV0_1;
  notes?: string;
};
```

Then `BatteryCase` may expose:

```ts
seriesStats?: BatteryFourRunSeriesStatsV0_1;
```

The older `mainPairStats` and `controlPairStats` placeholders may remain for compatibility until the UI and registry migration are complete.

## Current conclusion

The next implementation should define the four-run series stats shape first. After that, import real values only from inspected evidence-pack artifacts, with tests proving source paths and run roles.
